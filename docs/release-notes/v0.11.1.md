OctetLedger 0.11.1 fixes collector registration for portable packages installed by WinGet or a browser.

## Fixes

- **Collector starts after WinGet installation and upgrade.** The hidden VBScript launcher starts the collector through ShellExecute, which honors the Windows Internet zone mark carried by downloaded payloads. The launcher could block invisibly, producing `Collector could not be launched` with no log or PID. Registration now clears that mark from the executable it is about to launch.
- **Narrowly scoped unblock.** Only the currently running `octetledger.exe` with the official product name and an unchanged on-disk image is eligible. Arbitrary paths, other products, files replaced after process start, and Windows security policies are left untouched. Publisher authenticity still requires code signing.
- **Portable alias identity.** WinGet installs the command alias as a symlink to the package executable. Collector identity now compares resolved targets, so the worker is recognized, reported ready, and waited for during stop and uninstall instead of its PID file being discarded.

## Install or upgrade

Choose the Windows x64 or ARM64 ZIP, compare its SHA-256 with the matching checksum asset, extract it, and run **install.cmd**. Automatic collection requires Windows Script Host with VBScript enabled.

WinGet portable users: run `octetledger collector install` once after installing or upgrading. The previous 0.3.0 → 0.11.1 upgrade path is preserved: SQLite data and settings are kept, and the database migrates from schema 0 to schema 6.

OctetLedger 0.11.1 retains SQLite schema 6 for existing 0.11.0 databases; no migration is required.
